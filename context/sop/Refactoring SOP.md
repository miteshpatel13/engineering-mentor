# Refactoring SOP

1. Define why refactoring is needed.
2. Establish current behavior with tests or other verification.
3. Identify the smallest safe scope.
4. Refactor without changing behavior unless explicitly intended.
5. Preserve public contracts.
6. Run tests and static checks.
7. Compare performance when relevant.
8. Review the diff for accidental changes.
9. Document intentional architectural changes.
