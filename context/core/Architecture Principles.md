# Architecture Principles

## Principles

- Define clear responsibilities and boundaries.
- Keep business logic independent from infrastructure where practical.
- Prefer cohesive modules with explicit dependencies.
- Avoid unnecessary layers.
- Make dependencies directional and understandable.
- Design interfaces around stable contracts.
- Keep domain rules close to the domain.
- Consider scalability and failure modes early for critical paths.
- Preserve backward compatibility where required.
- Prefer evolutionary architecture over speculative complexity.

## Architecture Review

Evaluate:
- Responsibilities
- Coupling
- Cohesion
- Dependency direction
- Data ownership
- Failure handling
- Scalability
- Security boundaries
- Operational complexity
- Testability
